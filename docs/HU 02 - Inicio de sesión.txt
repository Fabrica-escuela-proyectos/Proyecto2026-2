Feature: HU-02 Inicio de sesión
  Como usuario registrado
  Quiero iniciar sesión de forma segura
  Para acceder a las funcionalidades correspondientes a mi rol

  Scenario: Inicio de sesión exitoso con credenciales válidas
    Given un usuario registrado está en la pantalla de inicio de sesión
    When proporciona su correo y contraseña correctos y el sistema los valida de forma segura
    Then el sistema le permite el acceso

  Scenario: Sesión activa tras el inicio de sesión
    Given un usuario registrado inició sesión exitosamente
    When el sistema le permite el acceso
    Then el sistema mantiene su sesión iniciada durante un tiempo determinado

  Scenario Outline: Intento de inicio de sesión con credenciales inválidas
    Given un usuario está en la pantalla de inicio de sesión
    When intenta iniciar sesión con "<credenciales>"
    Then el sistema rechaza el intento de acceso y no le permite ingresar a la plataforma

    Examples:
      | credenciales                              |
      | correo incorrecto y contraseña correcta   |
      | correo correcto y contraseña incorrecta   |
      | correo vacío                              |
      | contraseña vacía                          |

  Scenario: Protección de la información de acceso del usuario
    Given un usuario ha iniciado sesión
    When el sistema mantiene su acceso activo
    Then la información que identifica su sesión se protege en todo momento y no queda expuesta a personas no autorizadas

  Scenario: Expiración de la sesión
    Given un usuario cuenta con una sesión activa
    When se cumple el tiempo de duración de la sesión (1 hora)
    Then el sistema cierra automáticamente su acceso
    And le solicita iniciar sesión nuevamente para continuar usando la plataforma

  Scenario Outline: Protección de datos sensibles en los registros internos
    Given ocurre un intento de inicio de sesión "<resultado>"
    When el sistema guarda un registro interno de ese intento
    Then el registro no incluye la contraseña ni ninguna otra información sensible del usuario

    Examples:
      | resultado |
      | exitoso   |
      | fallido   |

  Scenario: Identificación del rol del usuario tras iniciar sesión
    Given un usuario inició sesión exitosamente
    When el sistema reconoce su cuenta
    Then el sistema identifica el rol asociado al usuario
    And le permite únicamente las funcionalidades correspondientes a ese rol

  Scenario: Solicitud de verificación adicional a cuenta administrativa
    Given un Administrador ingresa credenciales válidas
    When el sistema detecta que su cuenta requiere un paso adicional de verificación
    Then el sistema le solicita completar ese paso adicional

  Scenario: Acceso con verificación adicional correcta
    Given un Administrador ingresó credenciales válidas y el sistema le pidió la verificación adicional
    When completa la verificación correctamente
    Then el sistema le permite el acceso

  Scenario: Bloqueo de acceso con verificación adicional incorrecta
    Given un Administrador ingresó credenciales válidas y el sistema le pidió la verificación adicional
    When la verificación adicional es incorrecta
    Then el sistema no le da acceso

  Scenario Outline: Solicitud de confirmación adicional en operaciones sensibles
    Given un usuario autenticado (<quién la realiza>) intenta realizar la operación "<operación>"
    When el sistema identifica que esa operación requiere confirmación adicional
    Then el sistema le solicita completar esa confirmación antes de ejecutarla

    Examples:
      | operación                              | quién la realiza              |
      | cambiar su contraseña                  | cualquier usuario autenticado |
      | modificar los permisos de otro usuario | Administrador                 |

  Scenario Outline: Bloqueo de operación sensible con confirmación incorrecta
    Given un usuario autenticado (<quién la realiza>) debe confirmar la operación "<operación>"
    When la confirmación adicional es incorrecta
    Then el sistema impide la acción

    Examples:
      | operación                              | quién la realiza              |
      | cambiar su contraseña                  | cualquier usuario autenticado |
      | modificar los permisos de otro usuario | Administrador                 |
