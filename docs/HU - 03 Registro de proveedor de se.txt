Feature: HU-03 Registro de proveedor de servicios
  Como proveedor de servicios
  Quiero registrar mi negocio en la plataforma
  Para administrar mis servicios, horarios, recursos y reservas

  Scenario: Registro exitoso de proveedor con datos válidos
    Given un visitante no registrado está en el registro de proveedor
    When completa todos los datos personales y del negocio con información válida y envía la solicitud
    Then el sistema crea la cuenta del proveedor exitosamente
    And registra la información del negocio asociada a esa cuenta

  Scenario: Asignación del rol Proveedor
    Given un visitante se registró exitosamente como proveedor
    When el sistema termina el registro
    Then el sistema le asigna el rol "Proveedor" de forma controlada

  Scenario: Protección de la contraseña del proveedor
    Given un visitante se registró exitosamente como proveedor
    When su cuenta queda creada en la plataforma
    Then su contraseña queda guardada de forma segura
    And nadie, ni el equipo desarrollador ni quien administra la plataforma, puede verla de forma legible

  Scenario: Registro de proveedor con correo ya existente
    Given ya existe una cuenta registrada con el correo "proveedor@ejemplo.com"
    When un visitante intenta registrarse como proveedor con el correo "proveedor@ejemplo.com"
    Then el sistema rechaza la solicitud y no crea una cuenta duplicada
    And muestra un mensaje indicando que el correo ya está en uso

  Scenario: Registro de proveedor con formato de correo inválido
    Given un visitante está en el registro de proveedor
    When ingresa un correo con formato inválido, por ejemplo "negocio@@dominio", y envía la solicitud
    Then el sistema rechaza la solicitud y no crea ninguna cuenta
    And muestra un mensaje de error indicando que el formato del correo no es válido

  Scenario Outline: Número de celular con formato inválido en el registro de proveedor
    Given un visitante tiene nombre, correo, contraseña y datos de negocio válidos
    When envía la solicitud con el celular "<celular>"
    Then el sistema rechaza la solicitud y no crea ninguna cuenta
    And muestra un mensaje de error indicando que el número de celular no es válido

    Examples:
      | celular    |
      | abcde12345 |
      | 12345      |
      | 123        |
      | 1234567890 |

  Scenario Outline: Contraseña válida con un carácter especial permitido
    Given un visitante tiene nombre, correo, celular y datos de negocio válidos
    When envía una contraseña con mayúscula, minúscula, mínimo 8 caracteres y el carácter especial "<carácter especial>"
    Then el sistema crea la cuenta del proveedor exitosamente

    Examples:
      | carácter especial |
      | ¡                 |
      | *                 |
      | +                 |
      | °                 |

  Scenario Outline: Contraseña que no cumple la política de seguridad
    Given un visitante tiene nombre, correo, celular y datos de negocio válidos
    When envía una contraseña que incumple el requisito "<requisito>"
    Then el sistema rechaza la solicitud y no crea ninguna cuenta
    And muestra un mensaje indicando el requisito de seguridad no cumplido

    Examples:
      | requisito                              |
      | contener al menos una mayúscula        |
      | contener al menos una minúscula        |
      | tener mínimo 8 caracteres              |
      | contener al menos un carácter especial |

  Scenario Outline: Campo obligatorio faltante en el registro de proveedor
    Given un visitante está en el registro de proveedor
    When deja vacío el campo "<campo>" y envía la solicitud
    Then el sistema rechaza la solicitud y no crea ninguna cuenta
    And muestra un mensaje de error específico para el campo "<campo>"

    Examples:
      | campo              |
      | nombre completo    |
      | correo electrónico |
      | número de celular  |
      | contraseña         |
      | nombre del negocio |

  Scenario: El proveedor no puede autoasignarse un rol privilegiado
    Given un visitante está en el registro de proveedor
    When envía en la solicitud un rol distinto a "Proveedor", por ejemplo "Administrador"
    Then el sistema ignora el rol enviado y asigna el rol "Proveedor" de forma controlada
    And la cuenta queda registrada únicamente con el rol autorizado

  Scenario: Protección de la contraseña en el registro interno
    Given un proveedor se registra en la plataforma
    When el sistema guarda un registro interno de ese evento
    Then el registro no incluye la contraseña del proveedor
