Feature: HU-05 Gestionar roles y permisos
  Como administrador
  Quiero gestionar los roles y permisos de los usuarios
  Para controlar de forma segura quién puede acceder a cada funcionalidad

  Background:
    Given el sistema tiene los roles "Cliente", "Proveedor" y "Administrador" configurados
    And cada rol tiene permisos definidos sobre los recursos del sistema

  Scenario: Administrador asigna el rol "Administrador" a un usuario Cliente
    Given un Administrador autenticado y un usuario con rol "Cliente"
    When le asigna el rol "Administrador" a ese usuario
    Then el sistema actualiza el rol del usuario a "Administrador"

  Scenario: Creación obligatoria de MFA para el nuevo Administrador
    Given un Administrador asignó el rol "Administrador" a un usuario
    When el sistema actualiza el rol del usuario
    Then se activa de forma obligatoria la creación de MFA para el nuevo "Administrador"

  Scenario: Nuevo Administrador sin MFA completado no puede acceder
    Given un usuario recibió el rol "Administrador" y aún no completa la creación de MFA
    When intenta acceder como Administrador
    Then el sistema le deniega el acceso hasta que complete la creación de MFA

  Scenario: Administrador intenta cambiar el rol de un Proveedor
    Given un Administrador autenticado y un usuario con rol "Proveedor"
    When intenta cambiarle el rol a ese usuario
    Then el sistema rechaza la operación y no cambia el rol
    And informa que a los usuarios con rol "Proveedor" no se les puede cambiar el rol

  Scenario Outline: Administrador elimina un usuario
    Given un Administrador autenticado y un usuario con rol "<rol>"
    When elimina a ese usuario
    Then el sistema elimina al usuario en su totalidad

    Examples:
      | rol       |
      | Cliente   |
      | Proveedor |

  Scenario: Historial tras eliminar un usuario
    Given un Administrador eliminó a un usuario con rol "Cliente" o "Proveedor"
    When el sistema termina la eliminación
    Then el sistema guarda el historial de las funcionalidades que realizó el usuario
    And sus reservas, sitios y horarios no se consideran datos válidos

  Scenario: Cuenta eliminada sin acceso ni funciones
    Given un usuario con rol "Cliente" o "Proveedor" fue eliminado
    When intenta acceder a su cuenta o realizar cualquier función
    Then el sistema le deniega el acceso y no le permite ninguna función

  Scenario: Administrador intenta eliminar a un Administrador
    Given un Administrador autenticado y un usuario con rol "Administrador"
    When intenta eliminar a ese usuario
    Then el sistema rechaza la operación y no elimina al usuario

  Scenario: Administrador intenta asignar un rol inexistente
    Given un Administrador autenticado y un usuario con rol "Cliente"
    When intenta asignarle un rol inexistente
    Then el sistema rechaza la operación
    And responde con un error uniforme indicando que el rol no existe

  Scenario Outline: Usuario intenta modificar sus propios permisos o rol
    Given un usuario autenticado con rol "<rol>"
    When intenta modificar sus propios permisos o rol
    Then el sistema rechaza la operación
    And responde con un error uniforme indicando que no puede modificarse a sí mismo

    Examples:
      | rol           |
      | Cliente       |
      | Proveedor     |
      | Administrador |
